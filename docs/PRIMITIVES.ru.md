# Сопоставление примитивов, их функуионала и функциональности

В данный раздел попали сопоставимые примитивы из обоих языков. Те примитивы которые не имеют аналога в другом языке в данном разделе не рассматриваются.

## Мьютекс: `std::mutex` vs `std::sync::Mutex<T>`

| Операция            | C++          | Rust                       |
|---------------------|--------------|----------------------------|
| Захват с ожиданием  | `lock()`     | `lock()`                   |
| Захват без ожидания | `try_lock()` | `try_lock()`               |
| Освобождение        | `unlock()`   | Неявно, при `Drop` guard'а |

## Мьютекс с двумя уровнями доступа: `std::shared_mutex` vs `std::sync::RwLock<T>`

| Операция                        | C++                           | Rust                        |
|---------------------------------|-------------------------------|-----------------------------|
| Монопольный захват              | `lock()`                      | `write()`                   |
| Разделяемый захват              | `lock_shared()`               | `read()`                    |
| Монопольный захват без ожидания | `try_lock()`                  | `try_lock()`, `try_write()` |
| Разделяемый захват без ожидания | `try_lock_shared()`           | `try_read()`                |
| Освобождение                    | `unlock()`, `unlock_shared()` | Неявно, при `Drop` guard'а  |

## RAII-блокировка: `std::lock_guard` vs `MutexGuard`, `RwLockReadGuard`, `RwLockWriteGuard`

| Операция                                          | C++        | Rust   |
|---------------------------------------------------|------------|--------|
| Автоматическое освобождение при выходе из области | Деструктор | `Drop` |

## Однократная инициализация: `std::call_once` + `once_flag` vs `std::sync::Once`

| Операция                 | C++                       | Rust           |
|--------------------------|---------------------------|----------------|
| Выполнить ровно один раз | `std::call_once(flag, f)` | `call_once(f)` |

## Условная переменная: `std::condition_variable` vs `std::sync::Condvar`

| Операция                           | C++                             | Rust                   |
|------------------------------------|---------------------------------|------------------------|
| Ожидание                           | `wait(lock)`                    | `wait(guard)`          |
| Ожидание с предикатом              | `wait(lock, pred)`              | `wait_while(pred)`     |
| Ожидание с тайм-аутом              | `wait_for()`                    | `wait_timeout()`       |
| Ожидание с предикатом и тайм-аутом | `wait_for(lock, timeout, pred)` | `wait_timeout_while()` |
| Уведомить одного                   | `notify_one()`                  | `notify_one()`         |
| Уведомить всех                     | `notify_all()`                  | `notify_all()`         |

## Барьер: `std::barrier` vs `std::sync::Barrier`

| Операция                | C++                 | Rust     |
|-------------------------|---------------------|----------|
| Прийти и дождаться всех | `arrive_and_wait()` | `wait()` |


## Поток: `std::thread` vs `std::thread`

| Операция             | C++                       | Rust                        |
|----------------------|---------------------------|-----------------------------|
| Запуск               | `std::thread(f, args...)` | `spawn(f)`                  |
| Ожидание завершения  | `join()`                  | `join()`                    |
| Отсоединение         | `detach()`                | Сброс `JoinHandle`          |
| Идентификатор        | `get_id()`                | `JoinHandle::thread().id()` |
| Число доступных ядер | `hardware_concurrency()`  | `available_parallelism()`   |

## Атомарный указатель: `std::atomic<T*>` vs `AtomicPtr<T>`

| Операция                | C++                         | Rust                      |
|-------------------------|-----------------------------|---------------------------|
| Чтение                  | `load()`                    | `load()`                  |
| Запись                  | `store()`                   | `store()`                 |
| Обмен                   | `exchange()`                | `swap()`                  |
| CAS с повтором          | `compare_exchange_weak()`   | `compare_exchange_weak()` |
| CAS без ложных провалов | `compare_exchange_strong()` | `compare_exchange()`      |

## Атомарный флаг: `std::atomic_flag` vs `AtomicBool`

| Операция                              | C++              | Rust           |
|---------------------------------------|------------------|----------------|
| Установить и вернуть прежнее значение | `test_and_set()` | `swap(true)`   |
| Сбросить                              | `clear()`        | `store(false)` |
| Прочитать                             | `test()` (C++20) | `load()`       |

## Корутина: `co_await` / `co_return` vs `async` / `.await`

| Операция                     | C++         | Rust                  |
|------------------------------|-------------|-----------------------|
| Приостановка до готовности   | `co_await`  | `.await`              |
| Возврат значения из корутины | `co_return` | `return` в `async fn` |

# Тестовые сценарии

Одна схема замера на основные сопоставимые примитивы. Отдельных сценариев под каждый примитив нет:
меняется только **сценарий работы**, а сетка потоков, метрики и порядок прогона одинаковы везде.

## Сценарии работы

| Примитив C++         | Примитив Rust  | Одна операция                                                    |
|----------------------|----------------|------------------------------------------------------------------|
| `std::mutex`         | `Mutex<T>`     | `lock()` + пустая секция + освобождение                          |
| `shared_mutex`       | `RwLock<T>`    | `read()` + drop                                                  |
| `shared_mutex`       | `RwLock<T>`    | `write()` + drop                                                 |
| `call_once`          | `Once`         | вызов при уже выполненной инициализации                          |
| `condition_variable` | `Condvar`      | цикл «положить элемент -> `notify_one` -> потребитель проснулся» |
| `barrier`            | `Barrier`      | `arrive_and_wait()` на одну фазу                                 |
| `thread`             | `thread`       | `spawn` + `join`                                                 |
| `atomic<T*>`         | `AtomicPtr<T>` | `load()`                                                         |
| `atomic<T*>`         | `AtomicPtr<T>` | отдельно CAS-цикл до успеха                                      |
| `atomic_flag`        | `AtomicBool`   | `test_and_set()` + `clear()` как спинлок                         |
| `co_await`           | `.await`       | приостановка + возобновление на уже готовом ожидании             |

## Сетка потоков и параметры прогона

| Параметр              | Значение                      | Зачем так                               |
|-----------------------|-------------------------------|-----------------------------------------|
| Число потоков         | 1, 2, 4, 8, 16, 32            | Ускорение и точки перегиба              |
| Пачка для перцентилей | 100 операций (порядка 10 мкс) | Одна операция короче шага таймера       |
| Прогрев               | 1–2 с, отбрасывается          | Кэши, страницы, код, стабильные частоты |
| Повторы               | 10 прогонов на точку          | В отчёт идет медиана прогонов           |
| Привязка              | поток $k$ к ядру $k$          | Убирает миграции между ядрами           |

## Что замеряем в каждой точке сетки

| Метрика                       | Как считаем                                             | Раздел в [METRICS](./METRICS.ru.md) |
|-------------------------------|---------------------------------------------------------|-------------------------------------|
| Пропускная способность        | $N / T$, ops/s                                          | Throughput                          |
| Средняя задержка (Average)    | $\sum t_i / m$ по всем пачкам прогона                   | Latency                             |
| Задержка p50, p95, p99, p99.9 | $t_{\text{пачки}} / k$ по гистограмме пачек             | Latency                             |
| Ускорение                     | $T(1) / T(N)$                                           | Scalability                         |
| Эффективность                 | Ускорение / $N$                                         | Scalability                         |
| Использованная память         | `sizeof` структуры, байт на элемент, пик RSS            | Memory usage                        |
| Загрузка процессора           | $(\text{user} + \text{sys}) / \text{wall} \times 100\%$ | CPU utilization                     |

## Процедура, одинаковая для всех примитивов

1. **Проверка корректности.** Прогон с проверкой инвариантов до всяких замеров.
   Без этого можно померить быстрый неправильный код.
2. **Прогрев** 1–2 с, результат отбрасывается.
3. **Основной цикл по сетке:** для каждого $N \in \{2,4,8,16,32\}$ — прогон
   длительностью не меньше 1 с.
4. **Повтор** шагов 2–3 десять раз.
5. **Свёртка:** медиана по прогонам для каждой точки, перцентили — внутри прогона.
